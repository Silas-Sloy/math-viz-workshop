## 迭代1：2026-10-24 ε-δ 极限可视化（积木①）

### 我的 Prompt

> 帮我写一个 React 组件 EpsilonDelta.jsx，放在 src/components/visualizer/ 目录下。
> 功能要求：
> 1. 用 Canvas 画函数 f(x)=x² 在区间 [0, 2] 上的曲线
> 2. 标出极限点 x0=1 和极限值 L=1
> 3. 一个滑块控制 ε（范围 0.05 到 1，步长 0.01）
> 4. 根据 ε 计算 δ：数学上当 |x-1|<δ 且 δ≤1 时，|x²-1|=|x-1|·|x+1|<3δ，所以要保证 3δ<ε，取 δ=min(ε/3, 1)
> 5. 在图上用半透明蓝色横带标出 |f(x)-L|<ε 的区域（以 L=1 为中心，上下各 ε）
> 6. 用两条竖虚线标出 x0-δ 和 x0+δ 的位置
> 7. 右上角用 KaTeX 显示公式 ∀ε>0, ∃δ>0, |x-x0|<δ ⇒ |f(x)-L|<ε
> 8. 用 useMathStore（从 ../../stores/useMathStore 导入）读取和更新 epsilon、delta 状态，这样 AI 对话面板能拿到当前参数
>
> 样式要干净，配色用浅蓝主题。给我完整可运行的代码。

### AI 关键修改

> 生成 `EpsilonDelta.jsx`，核心结构：
> - 坐标映射函数 `xToPx` / `yToPx`，把数学坐标线性映射到 600×400 画布（留 50px 边距）
> - 分层绘制：坐标轴 → ε 蓝色横带（rgba(51,138,221,0.18)）→ δ 绿色竖带（rgba(29,158,117,0.12)）→ 抛物线（200 段折线保证平滑）→ δ 竖虚线 → 极限点实心圆
> - 滑块 `onChange` 中同步计算 `d = Math.min(eps / 3, 1)` 并写入 Zustand，实现 `setLimitState({ epsilon, delta })` 一次性更新

### 我的引导/纠偏

> 1. **δ 与 ε 不联动**：AI 初版把 `delta` 硬编码成 0.5，滑块拖动时 δ 不动，画面失去「收缩」的核心观感。改为在滑块 `onChange` 里实时计算 `δ = min(ε/3, 1)`，并同步写回 store，让 AI 对话面板能读到当前 δ。
> 2. **store 初始值不一致**：`epsilon: 0.5` 但 `delta: 0.5`，不符合 δ=ε/3 的关系，首屏就会出现「ε=0.5 而 δ=0.5」的错误对应。把 delta 初值改为 0.17（=0.5/3）。
> 3. **KaTeX 依赖风险**：原需求要求用 KaTeX 渲染公式，但当前 `katex` 版本 API 与 `react-katex` 封装存在兼容风险，且首个积木要保证「一次跑通」。改为用 Canvas `fillText` 直接绘制数学符号（保留 Unicode 的 ε/δ/²），KaTeX 统一留到第二阶段做统一公式渲染层。
> 4. **纵向区间判断**：AI 原本只画了 ε 横带没画 δ 竖带，无法体现「δ 区间内的 x 全部被压进 ε 带」这一关键视觉对应。要求补上 δ 半透明竖带 + 两条竖虚线。

## 迭代2：2026-10-24 导数切线逼近（积木②，DeepSeek 生成）

### 我的 Prompt

> 见 `docs/deepseek-prompts.md` 的 **Prompt ①**（完整原文，含项目硬性约束、代码风格样例、数学事实、绘图 8 条要求、输出格式）。
>
> 关键约束摘录：
> - 严禁 TypeScript / Tailwind / echarts / d3 / katex / 任何第三方包，只能 `import 'react'`
> - 数学事实写死：`k = ((1+Δx)² - 1) / Δx`，化简后恒等于 `2 + Δx`；切线斜率 `f'(1) = 2`
> - 要求割线「两端各延长 0.15 个 x 单位」

### AI 关键修改（DeepSeek 网页版 · 深度思考模式）

> 生成 `TangentApproach.jsx`，几个值得记录的处理：
> - **斜率用代数化简而非数值差分**：直接写 `const k = 2 + deltaX`，避开了 `(bY - aY) / (bX - aX)` 在 Δx 极小时的浮点误差，也把「k 恒等于 2+Δx」这个数学事实显式写在代码里
> - **割线延长**：`x1 = aX - ext`、`x2 = bX + ext`，`ext = 0.15`，并沿同一斜率外推 y 值，让割线看起来是一条贯穿的直线而不是两点之间的线段
> - **虚线状态隔离**：切线绘制用 `ctx.save()` / `ctx.restore()` 包住 `setLineDash([5,4])`，避免虚线状态污染后面 A/B 点的实心圆绘制
> - **依赖数组**：`useEffect` 依赖 `[deltaX]`，几何量 `aX/aY/bX/bY/k` 每次渲染重算，无闭包过期问题

### 我的引导/纠偏

> 1. **Prompt 里预先埋伏「割线延长 0.15 单位」**：如果不写这条，AI 只会连 A、B 两点画一条短线段，视觉上看不出「一条直线在旋转逼近切线」。这是我在下 Prompt 前就预判并写死的约束。
> 2. **Prompt 里去掉 KaTeX**：沿用迭代1 的结论，公式改用 Canvas 文字，降低一次跑通的风险。
> 3. **生成后数学校验**：Δx 拖到 0.01，界面显示 `k = 2.010`，与真实导数 `f'(1) = 2` 相差 0.5%，符合 `k = 2 + Δx` 的解析解。
> 4. **发现并修复 Vite 模板的全局样式污染**：AI 生成的组件本身没问题，但页面被 Vite 默认 `index.css` 影响——`#root` 固定 1126px 宽 + `text-align: center` + `prefers-color-scheme: dark` 深色模式覆盖。深色模式下页面变黑，而 canvas 是白底，演示视频会出现刺眼的黑白反差。重写 `index.css` 为锁定浅色主题的干净基础样式，并顺手统一了 range 滑块外观（演示画面更精致）。
> 5. **布局从「堆叠」改为「分节」**：两个 canvas 直接上下拼接会让评委看不出模块边界。把 `App.jsx` 改为数据驱动的 `sections` 数组渲染，每个模块带章节标签（第 1 章 极限 / 第 2 章 导数）+ 分隔线。后续新增积木只需往数组加一行。

### 我提前埋的约束（这条是关键）

Prompt 里我写了一段「已知陷阱」：

> 遇到标识符后面紧跟左括号时，不能一律当成函数调用。例如 `x(x+1)`，如果先把 x 当函数名再去查函数表，就会报"未知函数：x"。正确做法是先判断这个名字是否在函数表里。

**为什么写这一段**：我先自己写的一版就栽在这里，跑测试时 `x(x+1)` 直接抛"未知函数：x"。
把这个坑写进 Prompt 后，DeepSeek 一次生成就绕开了——它改用「标识符最长匹配切分」的办法：
把连续字母按已知函数名/常量名做最长匹配切成多个 token，`xsin(x)` 会切成 `x` + `sin`，`sinh` 整体切成 `sinh`。
这个解法比我原本设想的还稳。

### 验收结果

抽查产品实际要用的表达式：

| 表达式 | 结果 | 判定 |
|---|---|---|
| `x*sin(x)` 在 [-3,3] 的值域 | -0.18 ~ 2.00 | 正确（最低点在 x≈-4.49 之外） |
| `∫₀^π x·sin(x) dx` | 3.141593 | 正确（解析解就是 π，这是演示主用例） |
| `∫₀³ (x²+1) dx` | 12.000000 | 正确 |
| `x³-3x` 极值 | (-1, 2) 极大、(1, -2) 极小 | 正确 |

### 我的判断依据

## 迭代4：2026-10-24 通用绘图器 PlotCanvas.jsx（DeepSeek 生成）

### 我的 Prompt

完整版见 `docs/prompts/P2-通用绘图器.txt`（65 行）。核心是**把"画什么"和"怎么算"解耦**：

> 组件接口固定为 `<PlotCanvas spec={...} height={380} />`，spec 里只有描述：
> expr / domain / range / fill / fillFrom / marks / asymptote / note。
> 绘图器自己用 mathEngine 去采样、算值域、找极值、求零点，再把图画出来。
> 要求：高清屏适配、宽度自适应、遇到 y=null 断开不连线、悬停读数、滚轮缩放、拖动平移、编译失败不崩只显示错误。

**为什么这样设计**：后面 AI 拆题时只输出 `{"type":"plot","expr":"x*sin(x)","domain":[0,3.14],"fill":true}` 这样的 JSON，
不输出任何可执行代码。绘图器是固定的、被审查过的渲染器，AI 只负责"描述"，永远碰不到代码执行。
这一段写进技术文档，就是「安全 + 可复现」的直接论据。

### AI 生成后我做的事

| 动作 | 说明 |
|---|---|
| 落盘到 `src/components/plot/PlotCanvas.jsx` | 约定路径，import 路径 `../../utils/mathEngine` 正好两层，不用改 |
| 加一个临时预览入口 | 在 App.jsx 加第三段「引擎自检」，用 `x*sin(x)` 顶住页面，先看画得对不对 |
| 跑 `npm run build` | 25 个模块编译通过，1.27s，说明没有语法错误和未解析的依赖 |

### 验收方式

这一步**没法用断言测**（画面是画出来的），所以我用"三条肉眼可判"的标准：

1. 曲线是不是连续平滑、没有多画出一条跨越渐近线的竖线；
2. 极值点旁边有没有"极大/极小"标注，位置是不是在曲线的峰谷；
3. 鼠标悬停时右上角读数是否跟着走，`x` 和 `y` 是否与曲线一致。

选 `x*sin(x)` 是因为它一眼能验：它在 x≈±2.03 处有两个对称的峰（极大），在 x≈±4.9 处有两个对称的谷（极小），
零点在 x=0 和 x=±π、±2π。**如果图上这四个极值点和这几个零点的位置都对得上，说明引擎和绘图器是通的。**

### 迭代4 补记：一个 DeepSeek 没写出来的 bug，是我在浏览器里抓到的（2026-10-24 20:10）

**现象**：页面能渲染、坐标轴和刻度都在、控制台零报错，但曲线、面积、极值标注全部消失，悬停读数显示 "—"。

**定位过程**：我先排除了缓存（无痕窗口复现）和引擎（`node test-math.mjs` 31 条全绿）。真正破案靠的是三条画面证据的组合推理：
1. y 轴刻度是 ±0.8 —— 这是 `autoRange` 采样全失败时回退到 `[-1, 1]` 后 `niceTicks(-1,1)` 居中取 9 档的特征；
2. 没有 x 轴数字 —— `niceTicks(undefined, undefined)` 因 span=NaN 直接返回空标签；
3. 悬停读数 "x = —" —— hover.x 参与了 NaN 运算。

三条证据共同指向：**代码在拿 `undefined` 做数学**。往上追一层，发现 DeepSeek 生成的状态初始化是 `useState(baseDomain)`，而 `baseDomain` 是数组 `[-6, 6]`；但后续全部按对象读写 `view.a` / `view.b`——数组上取 `.a` 得到 `undefined`，整条渲染链路被 NaN 污染，又因为每个环节都"优雅地"吞掉了 NaN，控制台一片干净。

**修复**（人工，2 行）：初始 state 和重置 effect 改为 `setView({ a: baseDomain[0], b: baseDomain[1] })`，与滚轮/拖拽处理器的对象形状对齐。

**教训（写给以后的我）**：
- `npm run build` 只能抓语法和导入错误，抓不住"状态形状不一致"这类运行时逻辑 bug；
- 我验收引擎时只测了引擎本身，没测组件接线——**单元正确 ≠ 集成正确**；
- 浏览器截图里的"错误细节"（刻度范围、缺哪些元素、读数内容）本身就是调试信息，比一句"画不出来"值钱得多。

### 我做的事

### 真机测试暴露的一个风险 + 我的加固

第一次调用返回的 JSON **在第 350 个字符处 key 漏了双引号**，`JSON.parse` 直接抛错；第二次才正常。这说明 DeepSeek 的 `json_object` 模式**不是 100% 可靠**，偶发漏引号。

如果放任不管，用户真正输入题目时会随机遇到"AI 返回不是合法 JSON"的白屏/报错。所以我给 `parseContent` 加了一层 `repairJson` 容错：
1. 剥掉 ```json 围栏；
2. 截取第一个 `{` 到最后一个 `}`；
3. 用正则给漏引号的 key 补双引号（只匹配 `{, key:` 形式，**不破坏已合法的 JSON**）。

用两个用例验证过：①带围栏+漏引号+前面有废话 → 修复后可解析；②合法 JSON → 原样不动。

### 我的判断依据

不看"AI 说它对不对"，只认两条客观证据：
1. 真机返回的每个 `visual.expr` 都能被 mathEngine 的 `tryCompile` 编译通过（= 保证 P4 一定能画出来，不会因为 AI 给了坏表达式而白屏）；
2. 容错逻辑用"坏输入 → 修复成功"和"好输入 → 原样"两组用例验证。
